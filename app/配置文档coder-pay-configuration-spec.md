# Coder Pay（CP）完整配置信息文档

版本：v1.0  
日期：2026-06-05  
产品定位：面向个人开发者的网站自动收款平台  
适用范围：Web 后台、Android CP Watcher、开发者 API、收款码、设备、订单、回调、异常处理配置

---

## 0. 文档目标

本文件用于指导 Coder Pay（简称 CP）的产品设计、前端页面开发、后端接口开发、Android App 开发和上线验收。

CP 的核心目标是：

> 让个人开发者可以在自己的网站、工具、服务中接入微信 / 支付宝个人收款码，并通过 Android App 自动监听到账通知，完成订单匹配和支付成功回调。

CP 不做自动发货、不做会员系统、不做 AI 接入、不做企业支付、不做资金清算。CP 只解决一个核心问题：

> 个人开发者如何在网站上自动收款。

---

## 1. CP 配置方案总览

CP 的配置分为四层：

```text
第一层：Web 后台配置
第二层：Android App 配置
第三层：开发者 API 配置
第四层：运行监控与异常处理配置
```

完整运行链路：

```text
开发者注册 CP
  ↓
创建应用
  ↓
上传个人微信 / 支付宝收款码
  ↓
安装 CP Watcher Android App
  ↓
绑定设备
  ↓
开启通知读取权限、后台常驻、微信 / 支付宝通知
  ↓
开发者网站调用 CP 创建订单接口
  ↓
CP 返回二维码支付数据或支付页
  ↓
用户扫码付款
  ↓
Android 手机收到微信 / 支付宝到账通知
  ↓
CP Watcher 读取到账通知并上传到账事件
  ↓
CP Cloud 匹配订单
  ↓
CP 回调开发者 notify_url
  ↓
开发者系统确认服务开通
```

## 2. 核心原则

### 2.1 CP 只服务个人开发者

CP 的用户不是企业商户，也不是个体工商户，而是个人开发者。

目标用户包括：

```text
个人站长
独立开发者
小工具开发者
内容服务开发者
插件开发者
个人 API 服务开发者
```

### 2.2 资金不经过 CP

CP 的资金路径原则：

```text
用户付款 → 开发者个人微信 / 支付宝账户
```

CP 不做：

```text
代收
代付
托管
清算
提现
资金池
二清
```

CP 只做：

```text
订单创建
二维码调度
到账通知识别
订单匹配
支付成功回调
订单查询
异常补单
技术服务计费
```

### 2.3 Android App 是核心组件

CP 要实现全自动确认到账，必须有 Android App。

原因：微信 / 支付宝个人收款到账通知发生在开发者自己的 Android 手机上。CP Watcher 通过通知读取权限监听到账消息，再把结构化到账事件上传到 CP Cloud。

### 2.4 稳定性优先于功能复杂度

CP 不做复杂商业化工具。第一优先级是：

```text
不漏单
不误判
回调可靠
异常可处理
设备状态透明
```

## 5. 收款码配置

### 5.1 收款码配置入口

路径：

```text
Dashboard → 收款配置
```

CP 支持两类收款渠道：

```text
微信个人收款码
支付宝个人收款码
```

每个渠道支持三类二维码：

```text
不固定金额二维码
固定金额二维码
支付宝转账模式二维码
```

其中支付宝转账模式仅适用于支付宝。

---

### 5.2 不固定金额二维码

不固定金额二维码是用户扫码后手动输入金额的收款码。

字段：

| 字段 | 说明 |
|---|---|
| 渠道 | wechat / alipay |
| 二维码图片 | 开发者上传的个人收款码 |
| 二维码内容 | 系统解析二维码内容 |
| 绑定设备 | 指定使用哪台 Android 设备监听 |
| 状态 | 启用 / 停用 |
| 单笔最小金额 | 可选 |
| 单笔最大金额 | 可选 |
| 每日收款上限 | 可选 |

使用场景：

```text
任意金额订单
没有对应固定金额二维码时兜底
测试收款
```

支付页要求：

```text
明确提示用户：请手动输入金额 ¥X.XX
金额必须完全一致
付款完成后等待自动确认
```

---

### 5.3 固定金额二维码

固定金额二维码是微信 / 支付宝 App 生成的指定金额收款码。

字段：

| 字段 | 说明 |
|---|---|
| 渠道 | wechat / alipay |
| 固定金额 | 例如 29.90 |
| 二维码图片 | 固定金额收款码 |
| 二维码内容 | 系统解析内容 |
| 绑定设备 | 指定监听设备 |
| 状态 | 启用 / 停用 |
| 当前占用状态 | 空闲 / 已分配订单 |
| 每日使用次数上限 | 可选 |

推荐上传方式：

```text
如果商品价格是 35.00，可上传：
34.97
34.98
34.99
35.00
35.01
35.02
35.03
```

这样可以配合价格区间调度，提高二维码可用率。

---

### 5.4 二维码调度规则

当开发者创建订单时，CP 按以下顺序选择二维码：

```text
1. 选择订单指定支付渠道
2. 选择在线设备
3. 过滤停用二维码
4. 过滤超过限额二维码
5. 优先选择固定金额二维码
6. 在 price ± price_gap 范围内选择最接近订单金额的二维码
7. 如果多个二维码同样接近，选择当前未被占用且最近使用次数较少的二维码
8. 如果没有固定金额二维码，则使用不固定金额二维码
9. 如果没有任何可用二维码，返回 qr_limit
```

默认参数：

```text
price_gap = 0.10
expire = 300 秒
user_cache = true
```

---

### 5.5 价格选择策略

CP 支持三种价格选择模式：

```text
nearest：默认，选择最接近订单金额的二维码
floor：只选择小于或等于订单金额的二维码
ceil：只选择大于或等于订单金额的二维码
```

API 参数：

```text
price_type=nearest
price_type=floor
price_type=ceil
```

---

### 5.6 整数金额规避

为了避免整数金额订单冲突，CP 支持：

```text
no_int=true
```

规则：

```text
如果订单金额为 30.00，系统不使用 30.00 固定码，优先使用 29.99 / 30.01 等相邻二维码。
```

---

### 5.7 金额尾数匹配

CP 可选支持随机尾数模式。

示例：

```text
商品原价：29.00
实际支付：29.13
尾数：0.13
```

作用：

```text
减少同金额订单冲突
提高自动匹配准确率
```

限制：

```text
支付页必须清楚显示实际支付金额
回调中必须返回 price 与 pay_price
开发者应以 pay_price 为真实支付金额
```

## 7. 支付宝转账模式配置

### 7.1 模式说明

支付宝转账模式用于改善支付宝支付体验。

普通二维码模式下，用户需要扫码或长按二维码识别，可能还需要手动输入金额。支付宝转账模式下，CP 根据支付宝转账协议生成指定金额二维码，并返回支付宝 App 跳转链接。

适用渠道：

```text
alipay
```

不适用：

```text
wechat
```

微信端仍以二维码识别为主。

---

### 7.2 启用条件

启用支付宝转账模式需要：

```text
上传一张支付宝不固定金额收款二维码
配置 alipay_userid
绑定在线 Android 设备
支付宝支付助手通知正常
```

---

### 7.3 alipay_userid 配置

路径：

```text
Dashboard → 收款配置 → 支付宝 → 转账模式
```

字段：

```text
alipay_userid
支付宝昵称
支付宝账号备注
是否启用转账模式
```

获取方式：

```text
由 CP 后台提供获取 userid 的说明二维码或教程
开发者用支付宝扫码查看自己的 userid
复制 userid 到 CP 后台
```

---

### 7.4 接口返回

启用支付宝转账模式后，创建订单接口可返回：

```json
{
  "status": "ok",
  "cp_order_id": "cp_xxx",
  "pay_type": "alipay",
  "price": "29.90",
  "qr": "alipay transfer qr content",
  "qr_img": "data:image/png;base64,...",
  "jump_url": "alipays://platformapi/startapp?...",
  "expires_in": 300
}
```

支付页优先显示：

```text
打开支付宝付款
```

如果无法唤起支付宝，则显示二维码。

## 8. Android App 配置

### 8.1 安装要求

CP Watcher 需要安装在 Android 手机上。

建议设备：

```text
专用 Android 手机
长期插电
长期联网
不要作为主力手机频繁切换应用
登录开发者自己的微信 / 支付宝
关闭系统省电限制
```

不要求：

```text
root
Xposed
刷机
无障碍权限，除非后续功能需要
```

---

### 8.2 App 首页状态

CP Watcher 首页显示：

```text
Coder Pay Watcher

状态：监听中

支付宝：正常
通知权限：已开启
后台保活：建议检查
最近心跳：10 秒前

```

核心按钮：

```text
到账事件

退出登录
```

---

### 8.3 必须开启的权限

CP Watcher 必须引导用户开启：

```text
通知读取权限
通知显示权限
后台运行权限
自启动权限
忽略电池优化
网络权限
```

其中最关键的是：

```text
通知读取权限
```

没有通知读取权限，CP Watcher 无法读取微信 / 支付宝到账通知，也就无法自动确认订单。

---

### 8.4 微信配置

开发者需要在 Android 手机上登录自己的收款微信。

必须配置：

```text
开启微信通知
关闭微信勿扰模式
开启微信收款到账语音提醒
保持微信后台运行
不要在任务管理器中清理微信
如果电脑同时登录该微信，确保手机仍可收到收款通知
```

微信收款到账语音提醒路径参考：

```text
微信 → 我 → 服务 / 钱包 → 收付款 → 二维码收款 → 右上角更多 → 开启收款到账语音提醒
```

注意：不同微信版本路径可能不同，App 内应提供文字说明和截图占位。

---

### 8.5 支付宝配置

开发者需要在 Android 手机上登录自己的收款支付宝。

必须配置：

```text
开启支付宝通知
开启支付助手消息提醒
保持支付宝后台运行
不要在任务管理器中清理支付宝
```

支付宝支付助手路径参考：

```text
支付宝 → 搜索“支付助手” → 支付助手设置 → 开启接收支付消息提醒
```

### 8.10 到账事件上传

CP Watcher 上传到账事件时，默认只上传结构化数据。

字段：

```json

  "app_id": "app_xxx",
  "channel": "wechat",
  "amount": "29.90",
  "received_at": "2026-06-05T15:30:00+09:00",
  "notification_hash": "sha256_xxx",
  "confidence": 0.98,
```

### 8.11 本地缓存与补传

规则：

```text

每条事件生成唯一 hash
网络恢复后自动补传
Cloud 端按 hash 去重
补传事件仍进入订单匹配流程
```

## 9. API 配置

### 9.1 创建订单接口

接口：

```http
POST /api/pay/{app_id}
Content-Type: application/x-www-form-urlencoded 或 application/json
```

必填参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | 是 | 订单名称 |
| pay_type | string | 是 | alipay / wechat |
| price | string | 是 | 订单金额，保留两位小数 |
| order_id | string | 是 | 开发者系统订单号 |
| order_uid | string | 建议 | 开发者系统用户标识 |
| notify_url | string | 是 | 支付成功回调地址 |
| return_url | string | 否 | 前台跳转地址 |
| feedback_url | string | 否 | 付款异常反馈地址 |
| sign | string | 是 | 请求签名 |

可选参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| expire | 300 | 订单过期秒数 |
| round_robin | false | 是否启用多设备轮询 |
| price_type | nearest | nearest / floor / ceil |
| price_gap | 0.10 | 固定码候选价格范围 |
| no_int | false | 是否避开整数金额二维码 |
| user_cache | true | 同用户同金额未过期订单复用 |
| format | page | page / json |

### 9.2 创建订单返回

成功返回：

```json
{
  "status": "ok",
  "cp_order_id": "cp_20260605_xxx",
  "pay_type": "wechat",
  "price": "35.00",
  "pay_price": "35.00",

  "pay_url": "https://cp.example.com/pay/cp_20260605_xxx",
  "return_url": "https://developer.com/success",
  "feedback_url": "https://developer.com/feedback"
}
```

支付宝转账模式额外返回：

```json
{
  "jump_url": "alipays://platformapi/startapp?..."
}
```

错误返回：

```json
{"status":"sign_error"}
{"status":"order_payed"}
{"status":"order_expire"}
{"status":"plan_limit"}
{"status":"fee_error"}
{"status":"qr_limit"}
{"status":"device_offline"}
{"status":"missing_argument","info":"price"}
```

### 9.3 签名规则

CP 推荐默认使用 HMAC-SHA256。

签名字符串：

```text
name + pay_type + price + order_id + order_uid + notify_url + return_url + feedback_url
```

HMAC：

```text
HMAC_SHA256(sign_string, app_secret)
```

兼容模式支持 MD5：

```text
MD5(name + pay_type + price + order_id + order_uid + notify_url + return_url + feedback_url + app_secret)
```

规则：

```text
所有字段使用原始字符串
空字段使用空字符串参与签名
金额必须保留两位小数
签名结果小写
```

### 9.4 支付成功回调

CP 在检测到账并匹配订单后，向开发者 notify_url 发送 POST 请求。

参数：

| 参数 | 说明 |
|---|---|
| cp_order_id | CP 平台订单号 |
| order_id | 开发者订单号 |
| order_uid | 开发者用户标识 |
| pay_type | alipay / wechat |
| price | 订单原始金额 |
| pay_price | 实际支付金额 |
| status | success |
| paid_at | 到账时间 |
| sign | 回调签名 |

示例：

```json
{
  "cp_order_id": "cp_20260605_xxx",
  "order_id": "ORDER_10001",
  "order_uid": "user_123",
  "pay_type": "alipay",
  "price": "29.90",
  "pay_price": "29.90",
  "status": "success",
  "paid_at": "2026-06-05T15:30:00+09:00",
  "sign": "xxx"
}
```

开发者响应：

```text
success
```

CP 判定成功：

```text
HTTP 200 + body 包含 success
```

## 10. 订单匹配配置

### 10.1 自动匹配规则

到账事件进入 CP Cloud 后，按以下规则匹配订单：

```text
1. 同一开发者账号
2. 同一应用 app_id
3. 同一设备或设备组
4. 同一支付渠道 pay_type
5. 金额一致或符合尾数匹配规则
6. 订单状态为 pending / new
7. 订单未过期，或允许过期后匹配
8. 到账时间在订单创建后
9. 当前金额没有多个高置信度候选订单
```

---

### 10.2 匹配结果

匹配结果分为：

```text
auto_matched：自动匹配成功
multi_match：多个订单冲突
late_payment：订单过期后到账
no_match：到账事件无法匹配订单
amount_error：金额不一致
channel_error：渠道不一致
```

---

### 10.3 多订单同金额冲突

如果同一时间窗口内出现多个同金额订单：

```text
订单进入 review 状态
到账事件进入异常订单中心
不自动回调开发者
开发者后台手动选择匹配订单
匹配后 CP 发起回调
```

---

### 10.4 过期后付款

如果用户在订单过期后付款：

```text
到账事件标记为 late_payment
订单保持 expire 或进入 review
开发者可点击“确认已收款”
确认后 CP 回调开发者 notify_url
```

## 20. 最终产品判断

CP 的配置方案不应该完全照抄 BufPay，但底层原理必须一致。

最终方案：

```text
底层原理：个人收款码 + Android 到账通知监听 + 云端订单匹配
配置体验：Web 后台向导 + Android 权限体检 + 异常订单中心
接口能力：创建订单 + 查询订单 + 支付成功回调
运行保障：设备心跳 + 本地缓存 + 回调重试 + 手动补单
```

一句话：

> Coder Pay 是一个面向个人开发者的全自动个人收款平台。开发者配置自己的微信 / 支付宝个人收款码和 Android 监听设备，CP 负责订单创建、二维码调度、到账识别、订单匹配和回调通知，资金始终直接进入开发者自己的个人账户。
